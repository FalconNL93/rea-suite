Static census of the COM and C++ interface methods a game calls (winrt#27, part 1; the orchestrator, 2026-11-15). A port on winrt today learns of each missing method when the game stops on it, one at a time. This tool lists them up front from the game's binary. It lives in the RE suite because it reads game binaries, which no game repository holds.

Seeds:
- Factory imports: Direct3DCreate9, the D3DX*Create* functions, DirectInput8Create, DirectSoundCreate8, NxCreatePhysicsSDK and PhysXLoader's other exports.
- Per interface, the methods that hand out another interface, from the SDK headers, one table per SDK version: IDirect3D9::CreateDevice -> IDirect3DDevice9, CreateTexture -> IDirect3DTexture9, NxPhysicsSDK::createScene -> NxScene, NxScene::createActor -> NxActor, and QueryInterface by its IID constant.

Propagation:
- From each seed, follow the returned pointer (EAX, or the out-parameter) through stores to globals and struct fields. In MSVC-era code, globals and fields are the main channel.
- Every `call [reg+off]` whose reg was loaded from such a place maps to (interface, slot = off / 4).
- Function by function, with the decompiler's dataflow and xrefs.

Output: JSON. Per interface and slot: the method's name, the call sites (address, containing function), and a coverage line that counts the indirect calls left unresolved, so a reader knows how much the census missed.

Use: diffed against winrt's dump of what it answers (generated from winrt's own interface tables). The difference is the list of methods to answer, one interface at a time. Pilot: Lost: Via Domus (D3D9, D3DX, DInput8, DSound, PhysX 2.6.4). The census mode in winrt (a run that records every call) checks this tool's coverage, and this tool covers the paths that run did not reach.
