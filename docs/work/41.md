PSXRecomp's debug server as an oracle back end, and its lessons in docs/PS1.md (the harvest of 2026-11-15, item 3; the orchestrator). duke-nukem-ttk talks to PSXRecomp's debug server through `tools/psx_debug.py`, 28 lines of JSON over TCP; its `docs/research/2026-11-14-overlays.md` holds what it learned. Facts to write down (master-server PORTING lessons 1906aebb8, bc25faf05, 7fa974b65):
- The debug server is off unless `PSX_DEBUG_SERVER=1`, and a connection to a server that is off hangs instead of being refused.
- `read_ram 0x200000` returns all of RAM: the quick way to find where an overlay loads.
- From WSL, `timeout` doesn't stop the Windows process: send `quit` or use taskkill.exe.

Wanted: those facts in docs/PS1.md (small), then an `oracle` back end for PSXRecomp beside GDB and PPSSPP (medium). That lets a PS1 port's recompiled run be compared with DuckStation's at sync points. Related: #16 (PS1 overlays).
