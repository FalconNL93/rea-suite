Check a runtime's argument counts against the SDK slot tables in census diff (winrt and rea-suite, 2026-11-15). winrt's census mode returns from a method without a host function by its argument count, so a wrong count pops the wrong number of bytes and corrupts the guest's stack. winrt checked its Direct3D 9 and PhysX tables against rea-suite's generated slot tables (`common/rea_suite/data/census/`) by a script of its own, but cannot reach its DirectInput and DirectSound tables that way.

winrt will add `"args"` (and `"returns_float"`) per method to its answers file (rea-census/1, kind answers), in the tables' own convention: COM without `this`, PhysX with MSVC's hidden return pointer. Then `rea-suite census diff` warns on every method whose count or float return differs from the slot table of its `sdk` (or by interface name when `sdk` is absent), and docs/census.md says so.

Blocked until winrt's answers file carries `args`.
