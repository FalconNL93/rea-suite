Upstream in REA (rea-agents): keep the Ghidra project per image (from rea-suite#2, 2026-11-15). REA's Ghidra provider imports every target into a throwaway project: `dist/ghidra/GhidraLauncher.js` (rea-agents 6.8.0) runs `analyzeHeadless <runtime>/project rea-project -import <target> ... -readOnly -deleteProject`, so no snapshot spares the import. A snapshot keeps REA's answers, names and evidence, not Ghidra's database. On a large image the import outlasts the startup deadline every time: Alan Wake Remastered's 7 MB executable, against the 330 s default.

Wish: a provider setting (say `ghidra.project_dir`, or one kept beside the snapshot) that imports once into a lasting project keyed by the image's hash, and later opens it with `-process` instead of `-import`, read-only unless names are written back. The suite's workaround until then: rea-ghidra analyze (a lasting project), rea-suite pe for byte questions, Rizin's /r and axt for reference chains (docs/REA-KNOWN-ISSUES.md item 9a, PORT-TOOLS.md).
